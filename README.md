# Parser IP — GUI

**Parser_IP_EXE_GUI** — настольное приложение для **Windows** на **C# / WinForms**, которое помогает смотреть **исходящие TCP-соединения** выбранного процесса, **ведёт текстовый дамп** удалённых адресов и умеет **запускать `.exe`** с автоматическим логированием соединений.

Идея близка к утилите на Python [Parser_IP_EXE](https://github.com/mazixs/Parser_IP_EXE) (мониторинг процессов и сети), но реализована как **отдельное GUI-приложение** под .NET без внешних NuGet-зависимостей для сетевой части.

**Репозиторий:** [github.com/Andry495/Parser_IP_EXE_GUI](https://github.com/Andry495/Parser_IP_EXE_GUI)

---

## Возможности

| Функция | Описание |
|--------|-----------|
| **Список процессов** | Актуальный список процессов Windows с **поиском по имени**. |
| **TCP-соединения** | Таблица соединений выбранного процесса: локальный и удалённый endpoint, состояние. Обновление **каждые ~2 секунды**. |
| **Дамп в файл** | Запись в **обычный текстовый файл** (UTF-8): периодические снимки соединений, пометка **новых** пар `IP:порт`, строки **`UNIQUE_IP`** для новых IP. |
| **Запуск процесса** | Выбор `.exe`, аргументы, кнопка **«Запустить и дампить»**: старт процесса, выбор файла лога, дальнейшая запись соединений этого PID. |
| **Интерфейс** | Тёмная тема, карточки, статус-строка (текущее состояние и имя файла дампа). |

## Что приложение **не** делает (ограничения)

- Учитываются только **TCP**-соединения (данные берутся из расширенной TCP-таблицы Windows с привязкой к **PID**). **UDP** и другие протоколы в текущей версии **не отображаются**.
- Это **не сниффер пакетов** и **не прокси**: видны только **активные сокеты** процесса так, как их отдаёт ОС.
- Для части системных процессов или при ограниченных правах список соединений может быть **неполным** — см. раздел [Права доступа](#права-доступа).
- **Домены/CDN**, пинг, маршруты Keenetic и агрегация подсетей из оригинального Python-проекта **здесь не реализованы** (при необходимости можно добавить отдельно).

## Технологии

- **.NET 8** (`net8.0-windows`)
- **Windows Forms**
- **WinAPI:** `GetExtendedTcpTable` (`iphlpapi.dll`) — получение TCP-соединений с **идентификатором процесса (PID)**

Зависимости NuGet для работы приложения **не требуются**.

## Сборка и запуск из исходников

### Visual Studio

1. Клонируйте репозиторий или откройте папку с решением.
2. Откройте **`Parser_IP_EXE.sln`**.
3. Конфигурация **Debug**, платформа **Any CPU** → **F5** (запуск с отладкой) или **Ctrl+F5**.

### Командная строка

```powershell
cd путь\к\Parser_IP_EXE
dotnet build Parser_IP_EXE.sln -c Debug
dotnet run --project ParserIpExeMonitor\ParserIpExeMonitor.csproj
```

## Использование (интерфейс)

1. **Процесс**  
   - При необходимости введите часть имени в поле **«Поиск по имени…»**.  
   - Выберите процесс в выпадающем списке.  
   - Кнопка **«Обновить список»** перечитывает процессы с диска.

2. **Просмотр соединений**  
   В нижней большой области отображаются **активные TCP-соединения** выбранного PID (обновление по таймеру).

3. **Дамп**  
   - **«Начать дамп»** — выберите файл `.log` или `.txt`; в него начнут писаться снимки.  
   - **«Стоп»** — закрыть файл и остановить запись.

4. **Запуск своего приложения**  
   - Укажите путь к **`.exe`** (кнопка **«…»**), при необходимости **аргументы**.  
   - **«Запустить и дампить»** — после старта процесса выберите файл лога; дальше логируются соединения **этого** PID.

## Формат файла дампа

Файл — **обычный текст**, кодировка **UTF-8**. Удобно открывать в Блокноте, Notepad++, VS Code.

**Начало сессии:**

```text
=== Dump started 2026-03-23 14:30:00 ===
Process: chrome.exe (PID 12345)
```

**Периодически (на каждом цикле обновления):**

```text
--- Snapshot 2026-03-23 14:30:02 | connections: 5 ---
```

Далее **по строке на каждое соединение** в снимке (поля разделены **табуляцией**):

```text
2026-03-23 14:30:02	PID=12345	Remote=93.184.216.34:443	State=Established	New=1
```

- **`Remote`** — `IP:порт` удалённой стороны.  
- **`State`** — состояние TCP (как в системной таблице).  
- **`New=1`** — пара `IP:порт` встретилась **впервые** в этом дампе; **`New=0`** — уже была раньше.

Для новых уникальных удалённых IP дополнительно:

```text
UNIQUE_IP	93.184.216.34
```

**Конец сессии:**

```text
=== Dump stopped 2026-03-23 14:35:00 ===
```

## Публикация одним исполняемым файлом

Обычная команда **`Build`** в .NET даёт `.exe` + `.dll` + `.json`. Чтобы получить **один `.exe`** для раздачи, используйте **`publish`** (в проекте уже включено **`PublishSingleFile`**).

### Вариант A — компактный exe (нужен .NET 8 на целевом ПК)

```powershell
dotnet publish ParserIpExeMonitor\ParserIpExeMonitor.csproj -c Release -r win-x64 --self-contained false
```

Результат:  
`ParserIpExeMonitor\bin\Release\net8.0-windows\win-x64\publish\ParserIpExeMonitor.exe`

### Вариант B — один exe со встроенным runtime (без установки .NET)

```powershell
dotnet publish ParserIpExeMonitor\ParserIpExeMonitor.csproj -c Release -r win-x64 --self-contained true -p:EnableCompressionInSingleFile=true
```

Размер заметно больше; зато на целевой машине **не нужен** установленный .NET.

### Visual Studio

**ПКМ по проекту `ParserIpExeMonitor` → Publish** и выбор профиля из папки `Properties\PublishProfiles\`.

## Права доступа

- Для корректного чтения **полной** TCP-таблицы с привязкой к процессам в некоторых конфигурациях Windows может потребоваться запуск приложения **от имени администратора**.
- Если список соединений пустой или неполный: проверьте, что у процесса **есть активные TCP-соединения** в момент просмотра, и при необходимости запустите монитор **с повышенными правами**.

## Git и SSH (Windows)

Если `git push` по SSH выдаёт `Permission denied (publickey)`, а `ssh -T git@github.com` при этом успешен, часто Git использует **другой** `ssh`, чем интерактивная оболочка. Имеет смысл задать явно (подставьте свой путь к ключу):

```powershell
git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe -i C:/Users/ВАШ_ПОЛЬЗОВАТЕЛЬ/.ssh/id_ed25519_github -o IdentitiesOnly=yes"
```
